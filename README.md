# BountyDesk

An open agentic website for security research — a research desk for independent bug-bounty hunters, built for the [Open Agentic Web Challenge](https://cognizant-agenticweb.devpost.com/) (submissions close 11 Jan 2027, 23:00 WIB).

The desk is a public research page: a program-triage table (which bounty programs are live, free, and open to a new researcher, and what gates they carry), a checklist library, and a log of closed or out-of-scope findings. Agentified on top of it, the site publishes a network of three security agents that any visitor — human or agent — can discover from the manifest and talk to in the browser: a coordinator, a program-triage specialist, and a PoC-verification specialist. The agents answer only from the site's own data and read-only public sources; they never invent findings, never touch keys, and never run payloads.

## Run it locally

```shell
node ../spec-repo/skills/agentify-website/scripts/serve_site.mjs . --port 8080
```

Open http://127.0.0.1:8080/. (Run from this folder. The skill's server sends the CORS header on the public files; plain `python3 -m http.server` does not.)

To try the assistant, expand **⚙ AI model settings** and add your own provider key (bring your own key), or use **Connect with OpenRouter** for a free model in one click. Your key stays in your browser and is sent only to the provider you choose. Afterwards, select **Delete setup** under **Advanced settings** and close the tab: the tab keeps using the key until it is closed. On localhost the runtime also copies saved setups, keys included, into a cookie any local site can read — use a key with a low spending limit for local checks.

## Files

- `index.html`, `styles.css`, `script.js` — the desk page. `script.js` exports `App.page` (state reader + operations); the page's own buttons and the assistant share those functions.
- `data/programs.json`, `data/checklists.json`, `data/findings.json` — the desk's curated content, read by the site actions. Edit these to update the desk.
- `site.js` — boots the assistant in the page. `site-actions.js` — registers the site's actions with the runtime (see below).
- `bounty_desk.hocon` — source of truth for the network. `bounty_desk.network.json` — generated by the build; do not edit by hand.
- `agent-manifest.json` — public index of the network. `.well-known/awww.json` — an identical copy (the hackathon page names this location; the spec names `agent-manifest.json`). `.well-known/nsdeploy.json`, `.well-known/nsdeploy-agent.json`, `agent-mcp.json` — generated discovery files.
- `bridge/` — written by the build; other agent sites load `bridge/action-bridge.html` in a hidden frame before they run this network. Do not edit it.
- `runtime/` — the browser runtime (nsdeploy's runtime with the skill's edits for site actions and partner limits). Copy unchanged; see `runtime/README.md`.
- `tests/` — Node tests (`node --test "tests/*.test.mjs"`).

## Network

Network URL: the folder that holds `agent-manifest.json`, then the network name — for example `https://feriandi02.github.io/bountydesk/bounty_desk`.

Agents:

| Agent | Job | Tools |
| --- | --- | --- |
| `bounty_desk_coordinator` (front) | Routes questions, summarizes specialist answers, calls the peer trust check | `triage_specialist`, `poc_specialist`, `https://agent-atlas-phi.vercel.app/agent_atlas`, all `website_*` tools |
| `triage_specialist` | Program triage: PASS / CAUTION / FAIL with gates | `website_get_program_data`, `website_get_checklist` |
| `poc_specialist` | PoC verification: does the evidence prove the finding, or what is missing | `website_get_checklist`, `website_get_finding` |

Site actions (each becomes a `website_<name>` tool; only this site's visitors get them):

| Action | Effect | What it does |
| --- | --- | --- |
| `get_program_data` | read | One program from the triage table, by id or name |
| `get_checklist` | read | One checklist: `triage`, `poc`, `safe-testing`, `audit` |
| `get_finding` | read | One entry from the findings log |
| `search_programs` | read | Filter the program table (verdict, free, text) |
| `get_site_info` | read | Today's date, the site's facts, the Agent Atlas link |
| `save_triage_note` | write | Save the visitor's own note to their shortlist (their browser's localStorage only) |
| `delete_triage_note` | write | Delete one of the visitor's own notes |

Other agent sites that call this network get no `website_*` tools, so their assistant points to this site's page. The assistant sends the visitor's messages, and the page data it reads, to the LLM provider the visitor picks.

## Linked site

**Agent Atlas** — network URL `https://agent-atlas-phi.vercel.app/agent_atlas` (an independent directory and trust checker for the open agentic web). Before this desk asks another agent site anything, it asks Agent Atlas to check that site. The visitor sees a consent card (origin + purpose + token estimate) and approves or declines first; **Always allow** skips the card for that host until the page is reloaded. A request contains one or two short sentences only — never names, emails, phone numbers, or booking codes — though the runtime does not filter it, so the visitor checks it on the card. The partner's network runs in this browser on the visitor's key, with none of the partner's site tools, so it cannot give live availability or prices, and a call costs more than the card's token estimate. Verified with:

```shell
node ../spec-repo/skills/agentify-website/scripts/check_partner.mjs https://agent-atlas-phi.vercel.app/agent_atlas --origin https://feriandi02.github.io
```

## Hosting notes (GitHub Pages)

This site is hosted on GitHub Pages at `https://feriandi02.github.io/bountydesk/` (project site, under a subpath). Two honest consequences of that choice:

- **No custom headers.** GitHub Pages cannot send `Access-Control-Allow-Origin: *` on the public artifacts, so other sites cannot fetch this network's files cross-origin from a browser. Visitors can still use the whole site, and this site can still call Agent Atlas (which does send CORS headers). The manifest, network file, and bridge all work from this origin; the "other sites call this network" path is limited until the site moves to a host with header control.
- **Subpath, not domain root.** The manifest lives at `/bountydesk/agent-manifest.json` and the `.well-known/` copies at `/bountydesk/.well-known/`; discovery tools that look at the domain root will not find them. The network URL above (folder + network name) is the address partners use.

The assistant sends the visitor's messages, and the page data it reads, to the LLM provider the visitor picks. No key is ever committed to this repo.

## Build

Rebuild the network after editing the `.hocon` or the manifest:

```shell
node ../spec-repo/skills/agentify-website/scripts/build_network.mjs bounty_desk.hocon --manifest agent-manifest.json
node ../spec-repo/skills/agentify-website/scripts/build_network.mjs bounty_desk.hocon --manifest agent-manifest.json --check
node --test "tests/*.test.mjs"
```

After rebuilding, copy `agent-manifest.json` to `.well-known/awww.json` again so the two stay identical.
